## Real inference measurements

The synthetic benchmark uses clocked playback acknowledgments. It measures reply request to first generated PCM, excluding transcription, the native output device, and acoustic latency. Worker RSS includes the Python service and its descendants; it excludes the Swift app/WebKit and is not a precise measure of shared GPU allocations.

An initial 100-turn run without prefix caching slowed as conversation history grew: warm median 3.88 seconds and p95 6.53 seconds. This exposed the need for stable history trimming and cache reuse.

With a 1 GB RAM-only prefix cache and stable context boundaries, a second 100-turn run completed in 179 seconds with zero runtime errors. It started with 50 seeded exchanges, kept ASR resident, and deliberately interrupted every tenth reply. Warm median was 0.473 seconds and p95 0.531 seconds; cold first audio was 12.16 seconds. Peak worker RSS was 10.46 GiB and the slowest cancellation control call was 113 ms. These were short greeting prompts, and many replies became very short. This run preceded the final language/interruption-context fixes and should be read as a cache and resource stress check, not a general conversation latency promise.

The cached run also exposed language drift in repetitive mixed-language history. After clarifying the language instruction, a separate 36-turn text test produced English, Korean, and Japanese text for all 12 prompts in each language. A subsequent voice/interruption check still found one wrong-language response, so the final adapter adds a stable per-message language hint. Interruption cases also needed a fresh cache prefix and separate user-turn boundaries; rebuilding from the latest four exchanges avoids a long post-interruption prefill. These local comparisons do not establish the root cause inside the upstream model/runtime. These checks detect the expected writing system; they are not human review of fluency or pronunciation.

The final 18-turn voice/interruption regression started with 50 seeded exchanges, kept ASR resident, and interrupted every second reply. It had zero runtime errors and matched the expected writing system in all 18 generated replies. Warm first PCM was 1.779 seconds median and 1.938 seconds p95; most measured turns immediately followed an interruption. Peak worker RSS was 10.87 GiB and maximum cancellation control time was 140 ms. This is slower than uninterrupted cache hits because interrupted history starts a fresh prefix. The median 1.5-second aspiration was not met in this interruption-heavy test; the 2.5-second p95 aspiration was met for server first PCM. Raw report: `reports/local-benchmark-everyday.json`.

The final hands-free integration test replayed the included synthetic reference through actual VAD, Smart Turn, CPU ASR, dialogue, and TTS twice. Its sentence pause triggered an early turn followed by continued speech, exercising interruption recovery. Both final replies completed with no errors. After the end of the reference audio, ASR/turn readiness took 0.395 and 0.397 seconds; first PCM took 7.20 seconds cold and 1.82 seconds warm. One warm sample is insufficient for a latency distribution. No physical microphone was opened.

## Coordinated local speech update — October 14, 2026

Implementation is present, but **performance and human-speech acceptance are not complete**. The most important finding is that this Mac produces the default Fish 8-bit audio slower than real time. Delivering every new PCM packet immediately caused the reported popping: the player repeatedly ran out of samples inside words. Bounded phrase prebuffering greatly reduces those interruptions at the cost of waiting before a phrase. Long pauses between phrases still need improvement; lowering precision is not enabled automatically.

### What changed

- Capture and recognition readiness are separate. Already-granted microphone access starts synchronously; undetermined permission has an explicit waiting state. Converter resources are reused for an unchanged device format, channel 0 remains selected, and the converter tail drains before commit. Capture callbacks write into a bounded mailbox, rather than spawning one outbound task per packet. PTT bypasses VAD/Smart Turn; Hands-free preserves exactly 6,400 samples of preroll (400 ms) and the trailing captured audio.
- LVM2 microphone packets include capture UUID, sequence and sample offset. Legacy framing remains negotiated. New recordings, Stop and Mute invalidate stale capture/finalization work. Startup buffering is limited to ten seconds, each recording to 60 seconds. Raw recordings stay in RAM; a failed final pass retains only the bounded retry recording and releases it on cancellation/new capture/idle expiry. Unsubmitted drafts stay outside conversation history.
- Accurate mode uses CPU Nemotron Q8 drafts and a dedicated Qwen3-ASR 1.7B 8-bit MLX final pass. Fast mode uses Nemotron only. Context defaults to 320 ms; input and reply languages are independent. Vocabulary, sensitivity, pause tolerance, warm-up and explicit whole-segment compatibility mode are saved. A failed/timed-out final pass offers Retry, Edit and Use draft, and cannot silently start a reply.
- Text lookahead (four clauses), Fish synthesis, the audio reservoir and playback delivery are separate cancellable stages. The reservoir plus codec/IPC allowance stays below six seconds; native unacknowledged delivery remains one second. Short clauses begin after synthesis completes; long clauses start after filling the bounded reservoir. No canned filler, playback acceleration, smaller token limit, or automatic quantization downgrade was introduced.
- Repository-owned `fish_stream.py` and `fish_codec_stream.py` adapt the pinned provider. Four new codebook frames are decoded at a time, with causal convolution/transpose overlap, attention cache, absolute positions and final flush. The resampler preserves phase/history across 44.1→24 kHz chunks; packets are at most 80 ms. No growing-prefix re-decoding or installed `site-packages` edits are used. Whole-segment synthesis is a saved explicit fallback; a failed audible phrase is never automatically restarted.
- Reference tokens and a single immutable prompt prefix are cached with bounded retention. Weight-normalization folding is validated by codec parity. The fast codebook loop is compiled without changing weights or sampling. Idle speech caches can be trimmed on memory warnings; idle workers unload after ten minutes, while critical pressure cancels work and unloads workers without changing selected quality.
- Privacy-preserving timing export covers recognition, LLM, clauses, Fish, playback and native capture/release/Stop intervals. Vocabulary contents, prompts, transcripts and raw audio are excluded. Native/worker RSS and system swap are reported; macOS renderer processes that cannot be attributed through the process tree are explicitly marked unavailable, so the RSS sum is incomplete in that case. The 12/18 GB figures remain targets.
