# Local protocol v1

The native client generates a random token for each launch, starts Python on an ephemeral `127.0.0.1` port, and supplies `Authorization: Bearer …` on HTTP and WebSocket requests. Browser origins are rejected. No token is placed in a URL. One active session owns the inference workers. `/health` includes `session_active`; a reconnect waits for cleanup. Local same-user processes are outside this authentication threat boundary.

`/session` accepts JSON commands and binary microphone packets. Microphone audio is mono signed PCM16 little-endian, 16,000 Hz, with at most 8,192 payload bytes per packet. `ready` advertises supported microphone versions. `start` chooses `microphone_version: 2` and a `capture_id` UUID; LVM2 frames have the same 32-byte header layout as outbound LVA1, replacing the magic with `LVM2` and turn UUID with capture UUID. Sequence and sample offset must be contiguous. Stale captures are ignored; gaps/duplicates stop capture visibly. Omitted version retains the legacy raw-PCM parser. The ordered ingress queue is bounded by ten seconds of audio and each recording by 60 seconds.

Additional commands are `prepare`; `speech_settings` with the versioned validated settings object; `transcription_action` with `capture_id`, `retry`/`edit`/`use_draft`, and optional edited `text`; and `telemetry` with an allowlisted metric and a nonnegative process-local duration. The old `language` command updates both language preferences for compatibility. `commit` may carry a capture UUID; mismatched commits cannot submit another recording.

`preparation` events describe worker readiness independently from `listening`. Transcription events carry `capture_id` and `status` (`draft`, `finalizing`, `final`, `failed`). Only a final result or explicit draft/edit choice starts dialogue. Accurate finalization uses the complete RAM-only utterance with a `max(5, duration/2)` second budget capped at 30 seconds. Stop/new capture cancels it; failure keeps a bounded retry buffer and never silently submits a draft. Settings migrate an existing language preference into both input/reply fields once; new installations default to automatic. `/speech-diagnostics` exports bounded timing/configuration records without audio, text, vocabulary contents, or history.

Commands: `text` (`text`, `speak`), `start` (`mode`: `ptt`/`handsfree`), `commit`, `mute`, `stop`, `ack` (`turn_id`, `samples`), `profile` (`quiet`/`everyday`), `language` (`auto`/`english`/`korean`/`japanese`), `character` (`character_id`), `pressure` (`normal`/`warning`/`critical`), `avatar` (`avatar_mode`: `illustration`/`model`, `avatar_visible`: boolean, `reduced_motion`: boolean). Unknown fields and invalid values are rejected. The native client sends avatar state on connection, appearance/visibility changes, and before text or microphone input. A session without this handshake defaults to illustration mode and does not emit body gestures.

Events: `ready`, `turn`, `state`, `listening`, `transcript`, `text`, `expression`, `gesture`, `cancel`, `done`, `profile`, `character`, `metrics`, `notice`, `error`. Generated events carry a turn UUID. Client state must discard audio from other turns.

The dialogue model is instructed to begin every reply with one `[mood=EXPRESSION]` tag, choosing its own expression from `neutral`, `happy`, `curious`, `concerned`, `surprised`, `annoyed`, `embarrassed`, and `sleepy`. The streaming parser removes this metadata before display, speech synthesis, and history storage; missing or unknown expressions fall back to neutral. Once the prefix is resolved, one `expression` event carries the expression and `sample_offset: 0`, which the native client applies immediately for that turn, including text-only replies. No separate sentiment model runs. Emotion portraits and the 3D model show these expressions; the full-body illustration remains a fixed neutral image.

The parsed expression is also passed separately to Fish S2 Pro's speech worker. The worker creates allowlisted delivery tags and converts a happy standalone laugh into a chuckle; these Fish controls never appear in the displayed/stored transcript. Clauses are synthesized ahead of playback with bounded text/audio queues. The maintained adapter decodes incremental four-frame codebook batches, preserves codec/resampling state, and emits at-most-80 ms packets of 24 kHz mono signed PCM16. Safe prebuffering waits for a complete short clause or the bounded six-second reservoir; this avoids repeatedly starving the player when 8-bit synthesis is slower than real time. Whole-segment mode remains explicit. Outbound format, actual-playback acknowledgments and mouth timeline are preserved. Stop checks generation at semantic-frame boundaries and retains a 150 ms cooperative-cancel deadline before killing the worker. Partial audible phrases are never automatically retried.

The reply header continues with `[intent=greeting|explaining|acknowledging|uncertain|conversation]` and `[action=none|ACTION]`. These are literal selected values, not pipe-separated output. Supported requested action IDs are `wave`, `nod`, `explain`, `shift`, `step`, `twirl`, `raise-arms`, `shrug`, and `point`. `dance` and `laugh` are not action IDs. Requested actions take precedence over probabilistic conversational gestures; concerned/annoyed/sleepy replies suppress all body actions, including model-requested ones. `none` retains normal conversational selection. Unsupported action values fail closed. Legacy headers without intent/action still parse, and repeated tags are removed without retriggering actions.

Explicit actions also require matching movement words in the latest user message. A conservative English/Korean/Japanese filter vetoes translation, story and negation cues, and limits the prompt's action choices to matching capabilities. The model still decides whether a request is actually being made; the filter prevents unrelated tags (for example, `twirl` for a laugh request) from moving the avatar. It is not a complete language parser: uncommon phrasing and mixed requests may need to be restated directly. Ordinary intent-based conversational gestures retain their existing probability and cooldown rules.

At most one `gesture` event is sent per reply, carrying `gesture` and `wait_for_audio`. Native playback validates the ID, queues spoken gestures until audio begins, applies text-only gestures immediately and discards pending/stale events on interruption. The backend advertises/emits body actions only for visible Ari in model mode with motion enabled. This is a bounded avatar animation interface, not arbitrary model-selected code execution. New animations must be added to the renderer, native allowlist and backend capability list before the model may claim them. Voice capability text is composed after voice-reference resolution, so text fallback does not promise audible speech. Model wording may still be wrong; the action gate remains authoritative.

Server audio packets contain a 32-byte header followed by mono 24,000 Hz PCM16:

| Offset | Field |
| --- | --- |
| 0 | Four ASCII bytes `LVA1` |
| 4 | 16 raw UUID bytes in RFC display order |
| 20 | uint32 little-endian sequence, starting at 0 |
| 24 | uint64 little-endian starting sample offset |
| 32 | PCM payload |

The native player acknowledges the cumulative sample position only from AVAudioPlayerNode's `dataPlayedBack` callback. The server caps unacknowledged audio at 24,000 samples (one second); this is a backpressure window, not a startup buffer. It persists each completed spoken clause after its ending sample is acknowledged. An interrupted partial clause is conservatively omitted from future context. Generated text remains visible in history with an interruption marker.

Interrupted replies contribute only delivered text to assistant context, including an empty assistant turn when nothing was heard. Keeping user turns separate avoids combining conflicting language requests. The next user message carries an interruption note. The model never receives an invented assistant utterance consisting solely of an interruption marker. An empty model response produces a visible error instead of a successful empty turn.

Cancel is sent before worker cleanup. TTS first attempts cooperative cancellation, including an MLX synchronization, with a 150 ms acknowledgment deadline. If that fails, its process group is terminated. A stale generation cannot enqueue playback for the next turn. This deadline is a control-path policy, not a claim that physical acoustic cutoff was measured.

HTTP resources: `/conversations`, `/conversations/{id}` (GET/DELETE), `/memories` (GET/POST), `/memories/{id}` (PUT/DELETE), `/characters` (GET/POST), `/characters/{id}`, `/characters/{id}/persona` (PUT), `/characters/{id}/assets/{path}`, `/characters/import` (multipart POST), `/export`. Memory writes require explicit `approved: true`. Deleting or editing a memory stops current generation and unloads dialogue caches.


## Codex provider adapter (experimental, gated)

Local endpoints remain unchanged. `GET /backend` returns the saved provider plus readiness; `PUT /backend {"backend":"local"|"codex"}` saves selection only after validating Codex readiness. `GET /codex/status` refreshes a read-only compatibility probe. `GET /codex/diagnostics` exports bounded timing records and version evidence without audio, conversation text, screenshots or credentials. All use the existing launch token and browser-origin rejection.

`/codex/session` shares the session reservation with `/session`: local worker cleanup must finish before switching. It attaches to an existing, same-user Unix app-server socket with client identity `ari_companion`; it never launches another task engine. Closing Ari unsubscribes and closes its own voice/transport, never the daemon or underlying task.

Before the WebSocket handshake, the client rejects unrecognized socket links, unsafe directory owners/write permissions, non-private socket directories and extended access-grant ACLs. The inspected host creates `app-server-control.sock` as a link to a 64-hex-name socket in `/private/tmp/codex-daemon-UID`; only that specific layout is accepted, with the source directory, link owner, target directory, target socket and both identities checked. macOS `getpeereid`, `LOCAL_PEERPID` and `proc_pidpath` verify the connected peer's user and bundled executable before any protocol bytes are sent. The link/target device and inode are rechecked after connection. Desktop attachment evidence must refer to that same server PID and resolved socket. The pinned launcher routes desktop stdio through `codex_bridge.py`: the desktop retains its own initialize identity, startup overrides and environment, while Ari connects as `ari_companion`. Relay evidence additionally verifies the initialized connection, bridge executable/script, live desktop parent and process creation times. The relay has ordered bounded transport, forwards approvals unchanged, and never replays a request after disconnect. Its Unix-only host survives relay exit; mismatched runtime configuration is rejected instead of starting a competing host. Non-server CLI calls execute the bundled binary directly. A full desktop restart changes its tool pipe and verification identities, so retaining the old environment is rejected. The explicit launcher flag `--restart-idle-host` verifies host ownership and absence of other clients, active/uncertain tasks, queued work and background terminals before retiring that host. It never force-kills, and normal client closure never invokes this path. This does not implement per-application authorization against another process running as the same user. Normal activation additionally requires a `transport_access` live check. Acceptance fingerprints include Ari backend/native source and dependency locks as well as the inspected desktop/schema.

An explicit native/backend `--codex-validation-thread ID` launch uses transient Codex preferences and a single allowed task. `GET /backend` reports the effective provider plus `validation: {active, thread_id}`; production `available` remains unchanged. Validation requires real peer, home, desktop attachment, version, account/history/voice interfaces; only the release-acceptance record is deferred. Selecting another task, creating tasks, archive browsing, task-setting changes and saved backend changes are rejected. The session expires after one hour. It can perform authorized task work, so use a designated test task and the normal Codex approvals. It does not automatically send input, open the microphone, or record acceptance success.

Codex owns persisted history. Identity is `(provider=codex, host_id, thread_id)`; `host_id` is a stable digest of the canonical Codex home. Only identity and voice/presentation preferences are saved locally. `thread/read`, `thread/resume`, and `thread/timeline/list` pages reconcile canonical item IDs and positions. The inspected host returns newest pages first, with chronological entries within each page. Retention uses rollout positions rather than page arrival order; older pages cannot overwrite current voice ownership. Live ownership events win over concurrent history snapshots. Promoted-item references do not create duplicate messages. The view retains at most 2,000 recent items; the full archive remains in Codex. Archived selection uses read-only history without resuming the task. Submission stays blocked until history reconciliation completes; uncertain writes are never automatically retried.

Native control envelopes remain version 1, with `type:"codex"` and a validated nested command. Actions: `refresh`, `select`, `new`, `history_more`, `tasks_more`, `archived`, `voice_end`, `stop_task`, `voice_select`, `settings`, `approval`, `answer`. Slow history/catalog/text RPCs use a bounded eight-entry control queue, separate from microphone/ACK/mute/stop processing. Runtime event queues and pending RPCs are also bounded; overflow disconnects rather than silently discarding words or tool actions.

Normalized events include `codex_catalog`, `codex_selected`, `codex_history`, `codex_item`, `codex_state`, `codex_capability`, `codex_request`, `codex_request_resolved`, `codex_requests_clear`, `codex_audio_begin`, `codex_automation`, and `codex_disconnected`. Task state and voice ownership are independent. One-shot approval responses are removed locally before sending, and another client's `serverRequest/resolved` invalidates the card. Ari does not answer requests for other tasks or impersonate the desktop tool bridge.

History and live items carry `presentation: "conversation" | "activity"`. Tools and explicitly tagged assistant `commentary` appear in a separate collapsed Task activity panel in chronological order; user messages, voice transcripts, partial/final answers and questions stay in the conversation. Unknown or missing phases retain compatibility display behavior, rather than guessing whether text is an answer. Approval cards remain outside collapsed activity. Expanding details does not speak them. This is a disposable view of canonical Codex history, not a second conversation store or an extra summarization turn. Live text events never feed a local TTS worker; only realtime audio events play speech. The voice-session prompt requests natural conversation and concise verified task outcomes, suppressing routine command/log narration unless requested. Spoken compliance still requires live voice validation; a prompt is not an audio-content filter.

Voice uses `thread/realtime/start`, V3, host-authenticated WebRTC audio, startup context, host-default realtime model and automatic handoffs (`clientManagedHandoffs:false`). Voice catalog V2 entries are the currently inspected candidate list for V3; real account/voice acceptance is mandatory. Transcripts are never resubmitted through `turn/start`. Explicit typed input uses Codex's task-turn/steering behavior both inside and outside voice; `appendText` is context insertion and does not guarantee a task submission, reply, or persisted user message. Recognized voice-delegation envelopes appear as concise collapsed task activity, leaving their original canonical content intact. End voice and Mute do not interrupt a task. Stop suppresses later audio from the interrupted response until new user input.

The WebSocket voice route rejected ChatGPT sign-in on October 14 with `realtime conversation requires API key auth`. The inspected desktop also supports **host-owned WebRTC**: Ari supplies an SDP offer in `transport:{type:"webrtc",sdp:...}`, and the existing signed-in host creates the call and emits `thread/realtime/sdp`. An October 15 live signaling probe connected successfully using ChatGPT authentication with no API key or credential copying. This proves call setup, not spoken response/history acceptance. Ari now uses this path through pinned `aiortc==1.14.0`; it does not call the desktop's private HTTP endpoint or access its credentials.

The microphone opens only after both the start acknowledgment and WebRTC data-channel readiness. The native PCM sender feeds one 16 kHz media track with a one-second additional input limit; muted input is cleared and replaced by silence so GPT-Live's input clock continues. Muting never opens a physical device. Media is decoded/resampled continuously to mono 24 kHz, then delivered through the existing bounded native playback queue. Mirrored host audio events are ignored while WebRTC owns playback. Canonical host events remain the only source of transcripts and task history. A transcription boundary does not finish the continuous audio track. Closing, interruptions, failure and replacement invalidate local media identities; unmuting preserves the same connection and callbacks.

`codex_state.voice_unavailable_reason` carries a fixed sanitized explanation for the observed authentication rejection. Ari closes capture and blocks repeated Start voice attempts while typed tasks remain usable; reconnect or an account-change notification permits a new explicit check. Ari never changes shared-host authentication automatically. Start voice and the Codex shortcut toggle a persistent voice session; key release does not commit or end it. Voice requests disable reasoning-status relays and delegation filler and keep automatic handoffs in `thinking` mode. Spoken-summary compliance remains a live acceptance check.

The default omits `voice` so V3 chooses its own default; a V2 catalog default is not assumed to work for V3. Typed input uses `turn/steer` with `expectedTurnId` while a task is active, and `turn/start` only when idle. A rejected/uncertain steer never falls back to another start. Queued text/settings remain bound to the selected task at enqueue time. Stop discards pending work in both native and backend send queues; Mute retains typed task input. Delayed completion of an older turn does not clear the current turn's approvals/tools, and text deltas arriving after a completed canonical item are ignored.

Microphone framing is existing `LVM2` with capture UUID, sequence and sample offset, 16 kHz mono PCM16. Startup and stopped captures cannot reopen a later microphone session. WebRTC audio must have a supported rate, one/two channels and an ordered media clock. Its decoded PCM receives a session-scoped playback identity which rotates on interruption; reflected WebSocket audio is never a second playback source. Continuous stateful conversion produces existing `LVA1` 24 kHz mono packets of at most 80 ms. Startup buffer is 120 ms, adaptive to 300 ms after observed gaps; total queued/unacknowledged playback is capped at six seconds, with one second of native unacknowledged delivery. Actual played-sample ACKs and native mouth timelines remain authoritative. Invalid audio or sequencing visibly ends the session.

New tasks created in Ari register only the `ari_avatar_present` presentation tool, with whitelisted emotion/action arguments. It cannot perform external actions. Existing tasks without that tool use neutral/listening/thinking presentation. Cues are task/turn/voice scoped, expire, and obey visibility and Reduced Motion. Desktop-only dynamic tools must still be serviced by desktop; the shared-host routing acceptance gate explicitly tests this. Codex plugin disable metadata currently does not enforce capability filtering, so Ari does not expose a misleading security toggle.
